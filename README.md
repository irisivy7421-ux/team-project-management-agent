# Team Project Management Agent

一个面向团队协作群的自主项目管理 Agent 模板。它的目标不是替代项目负责人，而是把目标、责任、承诺、阻塞和决策变成可追溯的项目事实，并在风险出现时推动下一步行动。

## 包含什么

本仓库由三份协同但不重复的文档组成：

| 文档 | 负责什么 | 何时调整 |
|---|---|---|
| `Agent档案.md` | Agent 的身份、使命、职责和沟通方式 | 很少调整 |
| `用户档案.md` | 单个项目的目标、成员、协作范围和运行参数 | 每个项目复制后填写 |
| `行为准则.md` | 建盘、识别更新、跟进、升级、汇报和收尾的规则 | 需要改变管理方法时调整 |

这三份文档配合使用：档案回答“它是谁”，用户档案回答“它现在服务谁、按什么配置运行”，行为准则回答“它在什么条件下做什么”。

## 开始使用

1. 复制 `用户档案.md`，为目标项目创建一份私有配置。
2. 填写项目目标、交付物、负责人、决策人、协作群和任务主记录位置。
3. 与团队确认巡检、简报、催办冷却期和非工作时间的处理方式。
4. 将三份文档连同项目专属用户档案加载给 Agent；由团队指定的任务系统或项目账本保存实时状态。
5. 先以有限范围试运行，确认消息接收、任务写入、定时巡检和发送能力实际可用，再启用主动催办。

## Agent 应该做什么

- 把群内明确的认领、承诺、进展、阻塞、延期和完成信息关联到任务。
- 优先处理硬截止、关键交付、逾期承诺、影响下游的阻塞和长期未更新的重点事项。
- 用事实、影响和明确请求发起跟进；同一人的事项合并，避免重复催办和刷屏。
- 在需要资源、权限或范围取舍时升级给有决策权的人，而不是擅自改变分工。
- 按配置产出简报，区分已确认事实、待确认信息和风险判断。

## Agent 不应该做什么

- 不把“收到”“正在看”误认为实质进展。
- 不把猜测、估计或第三方转述写成确认的任务分配与截止日期。
- 不在没有事实依据时判定成员失职、任务逾期或项目走上关键路径。
- 不扩大可访问的群、私聊、文档或任务系统范围。
- 不把配置文本当作已经部署的监听、存储、调度或消息发送能力。

## 公开模板与私有配置

本仓库仅适合保存通用规则和空白模板。以下信息应保存在项目私有环境，不应提交到公开仓库：

- 真实成员姓名、用户 ID、联系方式和个人原因。
- 群聊 ID、文档链接、任务账本地址和内部项目资料。
- 访问令牌、密钥、密码、Webhook、OAuth 凭据或其他运行配置。
- 未公开的项目目标、客户信息、经营数据和项目进展。

## 运行边界

文档定义的是 Agent 的决策框架，不自带飞书监听、任务存储、定时调度或消息发送功能。实际部署前需要分别验证这些能力的权限、可见范围和执行结果。
